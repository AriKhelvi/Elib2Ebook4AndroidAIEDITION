# Elib2Ebook Android
Форк Elib2Ebook (upstream: OnlyFart/Elib2Ebook) с Android-приложением на .NET 10 MAUI.

## Структура
- src/ — код upstream: Domain, DomainServices, ExternalServices (парсеры сайтов). Менять только по необходимости.
- android/E2E.Droid — Android-приложение: Razor-страницы, Services, Platforms/Android.
- android/CoreSmoke — смоук-проверка ядра.
- tests/ — тесты upstream.

## Сборка
- dotnet build android/E2E.Droid/E2E.Droid.csproj -f net10.0-android -c Debug

## Правила
- Не коммитить APK, bin/, obj/, ключи и пароли.
- Ответы, комментарии, сообщения коммитов и описания PR — на русском.
- Описание PR — кратко: что изменено и как проверено.

## Ветки и слияние
- У каждого ИИ своя постоянная ветка: Claude — `claude/dev`, Codex — `codex/dev`. Работать только в своей ветке; в `master` и в чужую ветку напрямую не коммитить.
- Каждая задача — отдельный коммит (или несколько) в своей ветке с понятным сообщением.
- В `master` сливать только по прямой команде владельца. Перед слиянием: подтянуть свежий `master` в свою ветку, разрешить конфликты, собрать проект командой из раздела «Сборка».
- Если другая ветка уже слита в `master`, перед следующей задачей подтянуть `master` в свою ветку.
- Каждый пуш в `claude/dev` и `codex/dev` собирает APK в GitHub Actions (`android.yml`) — по нему владелец проверяет ветку до слияния.

## Тестовые (альфа) релизы
- Сборка для проверки на устройстве выпускается как pre-release GitHub по тегу на коммите своей ветки.
- Схема тега: `vX.Y.Z-alpha.<агент>.<N>`, например `v0.1.1-alpha.claude.1`.
  - `X.Y.Z` — следующая версия: последний стабильный тег `vA.B.C` с `C+1` (после `v0.1.0` — `0.1.1`), как у сборок веток.
  - `<агент>` — `claude` или `codex`, по своей ветке (`claude/dev`, `codex/dev`). Только строчные латинские буквы и цифры.
  - `<N>` — номер альфы этого агента для этой версии: 1, 2, 3… После нового стабильного релиза — снова с 1.
- Как выпустить: запушить коммит в свою ветку, затем одно из двух:
  - `git tag <тег> <коммит>` и `git push origin <тег>`;
  - если тег запушить нельзя (например, git в облачной сессии пушит только ветки) — ручной запуск `android.yml` на своей ветке с полем `alpha_tag` (Actions → Android APK → Run workflow, или через API: workflow_dispatch). CI сам поставит тег на собранный коммит.
  CI соберёт APK, подпишет ключом владельца и опубликует pre-release с APK и списком изменений. Вручную релиз не создавать, существующие теги не переставлять и не удалять: если номер занят, CI остановится — взять следующий `N`.
- Альфу выпускать, когда владельцу нужна сборка для проверки на устройстве. Стабильные релизы `vX.Y.Z` — только владелец, из `master`.
- Альфа-теги не влияют на версии сборок веток (`git describe` их пропускает).
- В альфе есть неприметные пометки для агентов: скрытый комментарий в описании pre-release, строки `#` в начале журналов из «Настройки → Отладка», подпись в «О приложении». Журнал диагностики владелец присылает в сессию — разбирать по нему.

## Code Review Rules
- Проверять ошибки логики, падения на Android, утечки ключей и паролей.
- Отмечать изменения в src/ (код upstream) и просить обоснование.
- Проверять, что проект собирается командой из раздела «Сборка».
