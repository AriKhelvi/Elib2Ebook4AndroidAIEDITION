# Litnet, ЛитРес и иллюстрации: жалобы на 0.2.2

## Что подтверждено

Семь журналов `E2E-download-log-20261115-*` относятся к релизу 0.2.2, коммиту `29126a0`.

- `070630`: журнал обрывается после заголовков ответа обложки; завершение задания неизвестно.
- `082957`, `093256`: после HTTP 200 приложение ждёт тело страницы серии, затем повторно загруженной
  обложки, до таймаутов 240/400 секунд. Это не доказывает зависание оглавления.
- `095859`, `100824`: ожидание тела обложки/страницы серии при таймауте 1000 секунд; пользователь отменил задания.
- `102159`: обложка и оглавление получены, таймаут при чтении первой пачки текстов глав; стек содержит HTTP/2 и Brotli.
- `115802`: доступные главы прочитаны, затем загрузка оборвалась на первой закрытой главе.

API Litnet сообщает `access=false` для закрытых глав. Модель не читала это поле, а строгая проверка
пустого текста, добавленная в 0.2.2, стала отклонять весь ознакомительный фрагмент.
HTTP 429 на отдельном скриншоте означает ограничение частоты запросов. Последующая проверка нашла
регрессию приложения, способную его провоцировать: пачки текста в 0.2.2 уменьшили со 100 до 10 глав.
Точный запрос, получивший 429 у пользователя, по скриншоту неизвестен.

Отдельного журнала ЛитРес нет. Найдена воспроизводимая причина показанного предупреждения HTTP 403:
общий HTTP-обработчик записывал предупреждение до завершения операции, хотя следующий штатный маршрут
ЛитРес мог вернуть полную книгу. Точный маршрут в пользовательском случае неизвестен.

## Изменения

- Litnet применяет выбранный диапазон, затем исключает только явно закрытые главы. Доступный фрагмент
  сохраняется с предупреждением. Неизвестный доступ, отсутствующий текст, повреждённый ответ и HTTP 429
  остаются ошибками. Покупки и права аккаунта приложение не меняет.
- Карточка и полная загрузка Litnet используют одни полученные метаданные, серию и исходник обложки.
  Каждая книга владеет отдельным временным файлом обложки; удаление превью не удаляет обложку результата.
  Кэш существует только в экземпляре загрузчика и сбрасывается при новой авторизации или смене книги.
- Запрос изображения идёт на настоящий адрес CDN, без подмены URI доменом основного сайта.
  Для Litnet выбран HTTP/1.1, получение необязательной серии ограничено 30 секундами, включая задержки.
  Это транспортная правка по журналам; они сами по себе не доказывают причину зависания именно в HTTP/2.
- Промежуточные HTTP 401/403/429 остаются в подробном журнале. Предупреждение пользователю формирует
  загрузчик по результату операции. Настоящие ошибки и предупреждения о неполном результате не подавляются.
- ЛитРес при HTTP 408/429/5xx прекращает основную загрузку, не подменяя сетевой сбой ознакомом.
- Импорт EPUB и FB3 ЛитРес учитывает отключение иллюстраций, сохраняя встроенную обложку EPUB/FB2.
  Подписи переключателей уточнены; отдельный файл обложки по-прежнему независим.
- Карточка предупреждений не сообщает об успешном сохранении при провале скачивания и не объявляет
  книгу неполной из-за любого предупреждения, например отсутствующей серии.

Общие изменения в ядре нужны для корректной оценки результата HTTP и импорта EPUB; ограничения сайтов
обрабатываются в соответствующих загрузчиках. Лимит манги и отдельная папка журналов сохранены.

## Проверки и границы результата

- 679 тестов ядра, 277 тестов Android-сервисов и 8 проверок интерфейса прошли.
- CoreSmoke собран: общий с Android конвейер, проверка сертификатов включена.
- Исходные книги Litnet `619747` и `621406` остановились на требовании входа для 18+ за примерно 4 секунды.
  Логины пользователей не использовались; покупки этих аккаунтов не проверены.
- Открытый пример `https://litnet.com/ru/book/otbor-dlya-temnoi-vedmy-b51246`:
  8 доступных глав из 21, 13 закрытых не запрашивались. За 13,89 секунды созданы FB2 (349771 байт)
  и EPUB (311168 байт), обложка 25335 байт сохранена, иллюстрации отключены.
  Оглавление и число глав готовых файлов проверены. Метаданные и обложка загружены по одному разу,
  все 7 HTTP-запросов использовали HTTP/1.1. Эвристика обнаружила возможный повтор заголовка в тексте;
  это отдельное форматирование, не ошибка скачивания.
- Реальный телефон и скачивание купленной книги с пользовательским аккаунтом этим прогоном не проверены.

## Повторная проверка числа запросов и общих настроек

Сравнение тегов 0.2.1 и 0.2.2 подтвердило увеличение числа запросов текста: 100 глав — с 1 до 10,
205 глав — с 3 до 21. Задержки, авторизация и низкоуровневые повторы HTTP между версиями не изменялись.
Проверка ознакома из 8 глав выше не могла обнаружить эту регрессию: он помещался в одну пачку.

- Восстановлен размер пачки 100. Проверка полноты ответа, доступных глав и обработка каждой пачки
  сразу после получения сохранены. Изменение upstream-загрузчика необходимо для устранения лишних запросов API.
- Ошибка 429 в карточке больше не запускает повторный полный `Get`. Серия и необязательные изображения
  также не поглощают 429; обычный 404 отсутствующей картинки остаётся предупреждением.
- В пределах одной очереди или диагностики оставшиеся книги ограниченного сайта пропускаются с объяснением.
  Другие сайты продолжают работать, новый ручной запуск создаёт новый сеанс. Уже отправленные параллельные
  запросы могут завершиться; приложение не обещает отозвать их после ответа 429.
- «Иллюстрации в главах» перенесены в «Настройки → Сохранение», рядом с отдельной обложкой.
  Прежнее значение настройки сохраняется. В CBZ страницы нужны независимо от этого переключателя.
- Пункт «Книги» полностью удалён из дополнительных файлов Android. Остались только аудио и картинки.
  Старые настройки мигрируют без неожиданного включения новых типов; конвейер исключает Books даже
  для старого набора «все». Исходный FB3 ЛитРес остаётся внутренним файлом для разбора, наружу сохраняется
  основная книга в выбранном формате. Фильтр экспортера ядра соблюдает выбранные типы дополнений.

Для книги на 205 доступных глав с карточкой и обложкой, без иллюстраций и перенаправлений, расчёт составляет
11 запросов в 0.2.1, 29 в 0.2.2 и 8 после исправлений (включая одну авторизацию).
Офлайн-проверки считают реальные вызовы подставного HTTP-обработчика на 8, 40, 100, 101 и 205 главах,
а также проверяют прекращение загрузки при 429. Это проверяет нагрузку приложения, но не воспроизводит
серверные лимиты Litnet и не гарантирует отсутствие 429 при любом IP или аккаунте.

Финальный локальный прогон: 692 теста ядра и 312 тестов Android-сервисов прошли. Среди них — миграция
дополнений, очереди после 429 и шесть интеграционных сценариев настоящего `BookPipeline` с подставным
загрузчиком: основной FB2 собран из внутреннего исходника, наружу выходят только выбранные аудио/картинки.
Реальные аккаунты и платные книги этим офлайн-прогоном не проверяются.

## Проверка с аккаунтом: повторная авторизация

На `fd434f7` проверка с предоставленным владельцем аккаунтом прошла для книги `620719`:
вход HTTP 200, одна глава собрана в FB2 и EPUB, встроенная и отдельная обложки сохранены,
иллюстрации отключены. Семь HTTP-запросов включали один штатный переход страницы серии;
метаданные, обложка, оглавление и текст запрошены по одному разу. Структура обоих файлов корректна.

Следующая книга через 30 секунд снова потребовала авторизации и получила HTTP 429 на единственном
запросе входа. Остальные пять случаев остановлены без запросов. Позднейшая отдельная попытка
входа получила HTTP 403 с JSON-ответом. Это воспроизводит исходный отказ авторизации;
само по себе снижение числа запросов глав его устранение не доказывает.

Устранён лишний вход на каждую следующую книгу: Android использует успешную сессию Litnet
в памяти процесса до 30 минут, без дополнительного запроса проверки. Хранятся максимум 32 сессии,
разделённые по сайту, области кэша и точным реквизитам; токены и отпечатки не пишутся на диск.
Одновременные загрузки одного аккаунта ожидают один вход. Изменение реквизитов требует нового входа.
HTTP 401 удаляет только отклонённую сессию и блокирует дальнейшие запросы того же загрузчика;
403 и 429 не запускают повторную авторизацию. Для Booknet поведение не меняется.

Правка снижает число входов после успешной авторизации, но не устраняет отказ первого входа.

После паузы реальный прогон с аккаунтом подтвердил повторное использование сессии:

|---|---|---|
| `620719`, «Тысяча и одна ночь с бывшим» | Вход 200, первая глава в FB2/EPUB, встроенная и отдельная обложки, без иллюстраций | 7, включая один вход и один переход страницы серии |
| `619747`, «Самый милый орк и жена понарошку» | Все 8 доступных глав из 40; 32 закрытые не запрашиваются; FB2/EPUB проверены | 6, без повторного входа |
| `621406`, «Чудовище Бунтарки» | Все 11 доступных разделов из 38, обложка сохранена, зависания нет | 6, без повторного входа |
| `640815`, «В объятиях красной планеты» | Карточка, обложка и оглавление 200, запрос текста одной главы 429 | 6, без повторного входа; дальнейшие случаи остановлены |

У `621406` проверка содержимого отметила три пустых раздела с названиями «Визуализация…»:
это разделы с изображениями, отключёнными выбранной настройкой. Они не доказывают потерю текста.
Название цикла у `621406` и `640815` не получено. В проверенной HTML-странице `640815`
нет заголовка `title`/`h1` и ожидаемых ссылок/подписи цикла, несмотря на HTTP 200;
данных для достоверного исправления селектора недостаточно.

Ещё один прогон `640815` после пятиминутной паузы с задержкой 4 секунды между запросами
также получил 429 на тексте одной главы, при успешных входе, карточке, обложке и оглавлении.
Это оставшийся сбой API, а не повторный вход или пачка из 100 глав.
Случаи `593192` и `581983` не запускались после этого ограничения; дополнительный контрольный
`51246` также не проверен с аккаунтом. Платные главы при закрытом доступе этого аккаунта не проверялись.
Полностью закрывать жалобы на 403/429 и название цикла по этому прогону нельзя.
