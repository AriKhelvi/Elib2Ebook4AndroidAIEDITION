# Жалобы после 0.2.1: критические ошибки

Разбор сообщений и журналов от 13–14 ноября 2026 года. Приоритет — невозможность скачать книгу, неполный результат и передача данных входа. Изменения в ядре нужны потому, что причины находятся в загрузчиках сайтов, а не в оформлении Android.

## ЛитРес: `/LitresCache`

Для книги `69258265` журнал сообщает `Read-only file system : '/LitresCache'`. Загрузчик создавал относительную папку до входа; рабочая папка Android не предназначена для записи. Исправление переносит кэш сеанса в приватные постоянные данные приложения, независимо от временной папки задания. Повреждённый и просроченный кэш не должен блокировать новый вход; отказ записи кэша не должен отменять успешную авторизацию. Пароль в кэш не записывается.

## Litnet: длительная загрузка без прогресса

Журналы `E2E-download-log-20261113-163047.txt` и `E2E-download-log-20261113-172425.txt` для книг `581983` и `640815` подтверждают получение карточки и обложки, затем паузу без сообщения о главе. Итоговой ошибки нет; журналы сохранены до истечения таймаута. Бесконечный цикл по этим данным не доказан.

Прежний код получал все тексты пачками по 100 и только потом начинал разбор с сообщениями о главах. Теперь пачки по 10 разбираются сразу, журнал сообщает о начале каждого запроса. Отсутствующие, пустые и повреждённые главы останавливают создание неполной книги. У публичной страницы `640815` подтверждён цикл «Марсианские Хроники» вне старого контейнера; добавлен селектор новой вёрстки.

Отдельная жалоба для `597410` — HTTP 403 в `Authorize`, до карточки. Уменьшение пачек её не исправляет. Требуется проверка API входа через сеть устройства; отказ сайта не скрывается и не превращается в гостевой «успех».

## Rulate/Bllate: вход и 100 глав

Журнал для Rulate `102135` содержит `NullReferenceException` в `GetAuthData` → `Authorize`. Код без проверки разыменовывал `meta[name=csrf-token]`. Теперь учитывается скрытое поле формы; при отсутствии штатной формы выдаётся понятная ошибка до отправки пароля. Ответ входа проверяется, страница проверки или повторная форма не считаются успешной авторизацией.

У Bllate `20455` получены публичные страницы: 100 записей на первой и 65 на второй (`?Chapter_page=2`). Текущая пагинация уже умеет их собирать. Жалоба о 100 скачанных главах при покупке всей книги остаётся открытой до проверки авторизованного оглавления и журнала нового APK. Число записей оглавления не означает, что все тексты доступны гостю.

## Neobook: HTTP 404 и проверка сеанса

На фотографии указан `https://neobook.org/book/wdR1jAc3MHtX08MY/` и HTTP 404. Полного журнала этого запроса нет. Из текущей сети не удалось получить ответ сайта за отведённое время, поэтому причина конкретного 404 не установлена.

При проверке загрузчика обнаружены отдельные дефекты: HTTP-адрес сайта с незащищёнными cookies сеанса, отсутствие проверки обязательных полей входа, зависимость JSON-парсера от точного окончания `;\n`. Исправлены HTTPS/Secure cookies, проверка входа и разбор одного JSON-значения независимо от переносов. Ответы без карточки/оглавления/текста дают явную ошибку. Эти изменения сами по себе не подтверждают восстановление доступа к указанной купленной книге.

## Остальные сообщения

Ficbook HTTP 403 в 0.2.1 относится к прежнему HTML-загрузчику; в ветке уже находится отдельный переход на протокол приложения Ficbook 1.7.0. Это не подтверждает доступность любой книги через любую сеть.

Несколько аккаунтов на сайт и объединение книг в один FB2 внесены в TODO как новые возможности. Они не входят в критические исправления этой партии. Работа приложения на Huawei с WebView 92 требует отдельного расследования запуска; нового журнала старта в этих сообщениях нет.

## Проверка

Отдельная кнопка «Проверить все сайты» использует версионированный каталог с 57 реальными книжными URL из прежнего аудита и сообщений пользователей. Для каждого сайта текущей сборки создаётся результат, в том числе явный пропуск. В полном реестре ядра это 85 хостов и 86 случаев (Яндекс Книги и комиксы отдельно); APK применяет свой список отключённых загрузчиков. Не найдены подтверждённые книги для включённых `bookstab.ru`, `freedlit.space`, `fb2.top`, `hotnovelpub.com`, `mangamammy.ru`, `noveltranslate.com`, `younettranslate.com`; причина указана в каталоге. Найденный пример MangaOvh использует неподдерживаемый загрузчиком поддомен, поэтому не выдаётся за рабочий.

Сценарий проверяет одну главу без входа, создаёт и проверяет FB2/EPUB либо CBZ с изображениями, затем удаляет временные файлы. Некоторые загрузчики получают книгу целиком. Лимит случая 90 секунд с кооперативной отменой, HTTP-таймаут не больше 60 секунд. Ошибки, ограничения доступа, пропуски и отмена не считаются успехом; таблица результатов не зависит от обрезки подробных строк. Проверка и обычное скачивание взаимно исключают запуск.

В «Подробный журнал» добавляется диагностический контекст: этап конвейера и его время, класс загрузчика, HTTP-запросы/ответы и перенаправления, структурные сведения об оглавлении, форме входа, кэше и JSON, отдельные строки стека исключения. Режим включается до запуска скачивания. Экспорт остаётся через существующую кнопку сохранения журнала. Тела запросов входа, cookies, токены, полные HTML/JSON со значениями и тексты книг не копируются; журнал ограничен по размеру. Диагностика не выполняет дополнительные сетевые запросы и не читает ответ повторно. Это повышает информативность отчёта, но не гарантирует воспроизведение любого сбоя без доступа к исходной среде.

Для изменённых загрузчиков добавлены изолированные HTTP-регрессии; они проверяют поведение без чужих паролей и покупки контента. Живые публичные проверки не заменяют повтор на телефоне с доступом пользователя. Стабильный релиз и слияние в master в эту задачу не входят.

Финальный локальный прогон: 534 теста ядра и 153 теста Android-сервисов прошли. Во время проверки также устранена гонка DarkNovels: общий словарь декодирования теперь создаётся один раз, вместо повторного заполнения каждым экземпляром загрузчика. Регрессия проверяет 64 параллельных создания и декодирования. CoreSmoke проверил соответствие всех запускаемых примеров зарегистрированным загрузчикам. Локальная Android-сборка ограничена отсутствием workload `maui-android` (NETSDK1147); сборки Debug и Release выполняются штатным GitHub Actions после отправки ветки.
